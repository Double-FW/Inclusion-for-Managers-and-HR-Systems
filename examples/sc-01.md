# AAC in a rapid meeting

**Synthetic case:** SC-01 · **Evaluation status:** Not run with users or an assistant.

## Situation

A team takes decisions during rapid spoken discussion. A colleague using typed AAC cannot secure a turn.

## Example response

The chair agrees a visible accessible contribution queue, protects completion time, accepts advance/later input and publishes actions for comment.

## Why this fits the guidance

The response aims for this outcome: People can contribute without avoidable time pressure or disclosure. It assigns the relevant owner and leaves any rights-sensitive decision with authorised people. Interim access should continue while outstanding work is resolved.

## Boundary

Do not infer cognitive capacity, finish contributions or require rapid chat.

## Verification and unresolved work

The organiser and participant review whether contributions shaped the decision; no live user test has been run. The action owner should agree a next update, an accessible review route and how unresolved work will be tracked. No real outcome, legal approval or user satisfaction result is claimed by this illustration.
